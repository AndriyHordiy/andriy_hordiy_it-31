1. NOT NULL
Для rooms.capacity встановлено NOT NULL. При додаванні номера без місткості отримано:
NOT NULL constraint failed: rooms.capacity

2. UNIQUE
Для guests.phone встановлено UNIQUE. При додаванні дубльованого номера отримано:
UNIQUE constraint failed: guests.phone
[lab_work_6](../lab_work_6)
3. CHECK
Для rooms.price_per_night встановлено:
CHECK(price_per_night > 0)
При введенні від'ємної ціни отримано:
CHECK constraint failed: price_per_night > 0
Правильне додатне значення було додано успішно.

4. DEFAULT
Для guests.email встановлено значення за замовчуванням. При додаванні гостя без email автоматично встановлено:
Гість не вказав ел. адресу =(

5. UPDATE
При зміні ціни номера на -1 через UPDATE отримано:
CHECK constraint failed: price_per_night > 0
Це підтверджує роботу CHECK під час UPDATE.

6. Практичний сенс
NOT NULL забезпечує обов'язкове заповнення місткості номера.
UNIQUE не дозволяє дублювати телефони гостей.
CHECK забороняє некоректну ціну.
DEFAULT автоматично заповнює email, якщо його не вказано.
