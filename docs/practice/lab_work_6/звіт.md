1) Оновив запис у фактовій таблиці bookings. Для бронювання з первинним ключем id = 1 змінив номер кімнати на 2:
UPDATE bookings SET room_id = 2 WHERE id = 1;
Умова WHERE id = 1 забезпечує оновлення лише одного конкретного запису.
2) Змінив місткість кімнати з id = 1 на 3 місця:
UPDATE rooms SET capacity = 3 WHERE id = 1;
Використання UPDATE є доречним, оскільки змінюється властивість уже існуючої кімнати, а не створюється новий об'єкт.
3) Спочатку за допомогою SELECT COUNT(*) перевірив кількість записів у таблиці bookings. Після цього видалив бронювання з id = 1:
DELETE FROM bookings WHERE id = 1;
Після видалення повторно виконав SELECT COUNT(*). Кількість записів зменшилася на 1, тому було видалено саме один рядок. 
ДО: sqlite> SELECT COUNT(*) FROM bookings;
10
ПІСЛЯ: SELECT COUNT(*) FROM bookings;
9
4) Перед видаленням прогнозував, що операція буде відхилена, якщо кімната id = 3 використовується хоча б в одному бронюванні. Після виконання DELETE SQLite відхилив видалення через наявність пов'язаного запису в bookings. Отже, фактичний результат відповідає прогнозу: кімната не була видалена, а пов'язані записи залишилися без змін.
